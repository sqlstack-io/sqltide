Streaming SQL pipelines for ClickHouse

Change live pipelines without downtime.

Write each step of your pipeline as SQL. When you change one, SQLTide can build the new version next to the running one and fill it from the stream history it keeps in ClickHouse. Check the results, then switch your queries over.

Try the demo Quickstart View on GitHub
$ pip install sqltide
  • ClickHouse
  • Python 3.12+
  • Open source · Apache-2.0

How a change goes live

By default sqt build drops the selected tables and refills them in place, while queries keep reading them. In virtual mode it builds next to the current tables instead, so you can check a change before your queries move to it. The steps below follow virtual mode.

  1. 01 · Write

    Write the pipeline in SQL

    Each model is a SQL file with typed columns. sqt compile checks them on your machine, without connecting to ClickHouse.

    Compile your models →
  2. 02 · Plan

    See what will change

    sqt plan lists the tables a change rebuilds and the history it replays. It doesn’t change anything in ClickHouse.

    Read a plan →
  3. 03 · Build and check

    Check the new version

    In virtual mode, sqt build creates the new tables next to the current ones and fills them. Your queries keep reading the current version while you compare.

    Build and check →
  4. 04 · Promote

    Switch your queries over

    Promoting points the views your queries read at the version you checked. A build never does this on its own.

    Promote a version →
